# 独立设备输入与输出

本次开发版本统一升级 SDK、Hub、Admin、Channel、Agent、Mobile 和 ESP32；不为旧固件保留特殊序列化分支。ESP32 实现位于工作树 `audio-capture-unification`。

## 开关语义

| 开关 | 关闭时 | 仍可继续 |
|---|---|---|
| 听说话 (`inputs.microphone`) | 不发布麦克风；不构造 ASR、VAD、声纹或语音打断分类器 | 已允许的回复输出、合法文本/主动任务输入 |
| 说话 (`outputs.speech`) | 不构造或调用 TTS，不生成回复语音 | ASR、LLM、文字、表情、动作 |
| 显示对话文字 (`outputs.dialogue_text`) | 不发布对话文字 | 语音、表情、动作 |
| 表情 (`outputs.expression`) | 不生成/发送面部表现命令 | 动作、文字、语音 |
| 动作 (`outputs.motion`) | 不发送动作命令 | 表情、文字、语音 |
| 提示音 (`outputs.audio_cue`) | 不播放产品提示音 | 不改变 TTS 权限 |

动作不再依赖表情开启。全部输出关闭是一种合法的无输出会话，不以 `NO_RESPONSE_OUTPUT` 拒绝启动，也不把正常完成误报成无可用回答。

听说话关闭意味着没有语音输入来源，不是关闭 LLM/TTS 的总开关。文本和主动任务仍须由现有合法入口触发；本次没有增加新的聊天输入页面或主动任务产品入口。

## 共用机制

设备声明能力；Hub 保存 Owner 的输入/输出选择，复用同一 CAS revision、审计和事务。输入是独立 `InputSelection`，不混入 `OutputSelection`。历史 wire 名称 `output_policy` 和管理路径 `/devices/{id}/outputs` 继续承载这个聚合，不增加并行权限数据库。

Channel 根据能力与选择生成会话计划和发布权限。LiveKit 使用显式调度的 ROOM worker，设备不必先发布一个麦克风轨道才能得到会话。计划中输入关闭时复用现有手动驱动的会话实现，跳过录音/PTT 控制器与音频模型；输出侧继续用统一输出计划。

在线权限更新通过 LiveKit UpdateParticipant 收敛；失败时 binding 标记为尚未收敛，复用 reconciliation 重试。旧 revision 的异步回调不能重新放宽权限。计划变化沿用已有会话重建流程，不承诺正在生成的一个回答无缝跨越权限变更。

Mobile 请求会话不再发布占位麦克风；输入关闭时不请求系统麦克风权限，也不启动本地 VAD。ESP32 分别初始化 capturer/renderer，按独立发布/订阅方向建立连接，输入关闭不再拒绝整个连接。

## 生成与费用

- 说话关闭：省去 TTS 请求和音频流量，文字回复仍需要 LLM。
- 文字关闭但说话开启：TTS 仍需要同一份回复文本，因此不能承诺节省这部分 LLM token。
- 语言输出都关闭：响应 schema 禁止 public_text；只保留所选的非语言意图。
- 表情、动作都关闭：不要求模型生成姿态、强度等表现字段；所有输出都关闭时用最小终结响应完成已有处理。
- 输入、输出都关闭且没有其他有效输入时，不触发新的模型推理。若仍有合法任务输入，理解、工具调用等所需 LLM 消耗仍然存在。

这些是调用路径约束，不是实测账单降幅。
